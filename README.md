# AI-помощник для подготовки товарных описаний

Прототип сервиса, который по данным о контрольно-измерительном приборе формирует черновик карточки товара для B2B-интернет-магазина: SEO-заголовок, SEO-описание, ключевые характеристики, поисковые запросы, коммерческий блок и список недостающих данных.

## Что реализовано

- Приём данных через веб-форму, JSON-редактор в интерфейсе или JSON API.
- Генерация карточки через `ChatOpenAI` из LangChain и OpenAI-совместимый API (`https://ollama.rety87nm.ru/v1`).
- Строгий промпт: модели запрещено добавлять характеристики, которых нет во входных данных.
- Детерминированное формирование блока «Ключевые характеристики» из входного `specs` — это исключает выдумывание технических значений.
- Проверка длины SEO-заголовка, SEO-описания и количества поисковых запросов; при нарушении — до трёх попыток генерации с обратной связью.
- Понятные ошибки для некорректного JSON, пустых полей, таймаутов и ошибок LLM.
- Результат в JSON и Markdown, кнопки копирования в интерфейсе.
- Два демонстрационных товара в `data/products.json`, готовые результаты в `examples/`.

## Стек

- Python 3.11+
- FastAPI + Uvicorn
- Pydantic
- LangChain (`langchain-openai`, `langchain-core`)
- python-dotenv
- Jinja2
- Ванильный JavaScript/CSS без сборщика и внешних CDN

## Быстрый запуск

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

cp .env.example .env
uvicorn app.main:app --reload
```

Откройте http://127.0.0.1:8000.

Проверка доступности LLM:

```bash
curl http://127.0.0.1:8000/api/health
```

Генерация карточки из консоли:

```bash
curl -s http://127.0.0.1:8000/api/generate \
  -H 'Content-Type: application/json' \
  -d '{
    "name": "Манометр показывающий DM 02",
    "manufacturer": "Манотомь",
    "specs": {
      "диапазон измерений": "0–1,6 МПа",
      "класс точности": "1,5",
      "присоединение": "G1/2",
      "диаметр корпуса": "100 мм"
    },
    "description": "Прибор предназначен для измерения избыточного давления неагрессивных к медным сплавам жидкостей и газов."
  }' | python3 -m json.tool
```

Перегенерация примеров:

```bash
python scripts/generate_examples.py
```

## Конфигурация

Настройки читаются из переменных окружения или файла `.env` (он исключён из Git). Все параметры объявлены как модульные константы в `app/config.py`, файл `.env` подхватывается через `python-dotenv`.

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `OLLAMA_BASE_URL` | `https://ollama.rety87nm.ru/v1` | OpenAI-совместимый базовый URL |
| `OLLAMA_MODEL` | `bonsai2:27b` | Имя модели |
| `OLLAMA_API_KEY` | пусто | Необязательный Bearer-токен |
| `LLM_TIMEOUT` | `120` | Таймаут одного запроса, секунды |
| `LLM_MAX_RETRIES` | `2` | Повторы при сетевых ошибках и HTTP 429/5xx |
| `LLM_TEMPERATURE` | `0.2` | Температура генерации |
| `LLM_MAX_TOKENS` | `1600` | Максимум токенов ответа |

API-ключ не хранится в коде. Для текущего стенда ключ не требуется: `ChatOpenAI` получает заглушку, чтобы OpenAI-совместимый клиент мог инициализироваться, а при заданном `OLLAMA_API_KEY` используется реальный `Authorization: Bearer ...`.

## API

### `POST /api/generate`

Вход:

```json
{
  "name": "Манометр показывающий DM 02",
  "manufacturer": "Манотомь",
  "specs": {
    "диапазон измерений": "0–1,6 МПа",
    "класс точности": "1,5"
  },
  "description": "Прибор предназначен для измерения избыточного давления..."
}
```

Обязательно наличие `name` и хотя бы одного из полей `specs` / `description`.

Выход:

```json
{
  "card": {
    "product_name": "Манометр показывающий DM 02",
    "manufacturer": "Манотомь",
    "seo_title": "...",
    "seo_description": "...",
    "key_specs": [{"name": "диапазон измерений", "value": "0–1,6 МПа"}],
    "search_queries": ["..."],
    "commercial_block": "...",
    "missing_fields": ["..."],
    "warnings": []
  },
  "markdown": "# ...",
  "meta": {
    "model": "bonsai2:27b",
    "generated_at": "...",
    "attempts": 1,
    "duration_ms": 12000,
    "missing_input_fields": []
  }
}
```

Ошибки:

- `422` — некорректный входной JSON или данные, которые не удалось превратить в карточку.
- `502` — ошибка LLM/сети.
- `504` — таймаут LLM.

### `GET /api/health`

Проверяет доступность LLM и возвращает имя модели и список доступных моделей.

### `GET /api/examples`

Возвращает демонстрационные входные данные.

## Промпт и принятые решения

Полный системный промпт находится в `app/prompt.py`. Основные решения:

1. **Запрет на выдуманные характеристики.** Модели явно запрещено добавлять, округлять или изменять технические значения. В пользовательский промпт передаётся только JSON товара и список уже выявленных пропусков.
2. **Ключевые характеристики не генерируются моделью.** Они собираются в `app/service.py` напрямую из `specs`. Пустые значения получают пометку «данных нет». Это надёжнее, чем доверять числа модели.
3. **Валидация результата и повторные попытки.** Проверяются: заголовок ≤ 70 символов, описание 800–1200 символов, 3–5 поисковых запросов. Если требование нарушено, модель получает точное замечание (например, «описание 640 символов») и генерирует ответ повторно, до трёх попыток.
4. **JSON-режим LLM.** `ChatOpenAI` настроен через `model_kwargs={"response_format": {"type": "json_object"}}`, а отключение reasoning передаётся в `extra_body={"chat_template_kwargs": {"enable_thinking": False}}`. Повторы при сетевых ошибках и HTTP 429/5xx реализованы в `LLMClient`, чтобы сохранить единый бюджет попыток.
5. **Защита от неполных данных.** Валидатор сам находит отсутствующие `manufacturer`, `description` и пустые значения `specs`, а ответ модели дополнительно фильтруется: нельзя отметить как отсутствующее то, что реально передано.
6. **Постпроверка на выдуманные данные.** Готовый текст проверяется на числа, единицы и технические термины (`питание`, `материал`, `степень защиты`, `интерфейс`, `сертификат` и т. п.), которых нет во входных данных. Фразы с неподтверждёнными сведениями удаляются, заголовок при необходимости заменяется безопасным вариантом. Если после очистки описание стало короче 800 символов, оно дополняется только фактами из `specs`/`description`.
7. **Ограничение контекста.** Входные данные передаются компактным JSON, ответ ограничен 1600 токенами. Для очень длинных паспортов описание стоит предварительно сокращать.

## Демонстрационные результаты

- `examples/product_1.json`, `examples/product_1.md` — полный товар.
- `examples/product_2.json`, `examples/product_2.md` — товар с незаполненными производителем, описанием и частью характеристик; в результате явно перечислены недостающие данные.

## Ограничения

- Нет базы данных, истории генераций, авторизации и админ-панели — по условиям задания это не требуется.
- Нет потоковой выдачи токенов: ответ возвращается целиком.
- Проверка «отсутствия выдуманных характеристик» в свободном тексте эвристическая: структурные `key_specs` защищены детерминированно, но маркетинговый текст теоретически может содержать общую формулировку, которой не было во входных данных. Промпт и повторная валидация снижают этот риск.
- Модель `bonsai2:27b` на стенде работает без API-ключа; для другого провайдера потребуется задать `OLLAMA_BASE_URL` и `OLLAMA_API_KEY`.
- Нет ограничения частоты запросов и очереди: для production нужны rate limit, кэш и логирование.

## Возможные улучшения

- Перейти на `ChatOpenAI.with_structured_output()` с Pydantic-схемой для ещё более строгого ответа.
- Добавить кэширование по хэшу входных данных.
- Сделать пакетную обработку и экспорт в CSV/XLSX.
- Добавить проверку числовых значений регулярками и сверку с `specs`.
- Вынести промпты в конфигурацию и добавить A/B-тестирование.
- Добавить Docker и CI.

## Тесты

```bash
pip install pytest
pytest -q
```

Тесты проверяют валидацию входа, поиск пропусков, формирование характеристик, обработку проблемного ответа модели и Markdown-рендеринг. Сетевые вызовы в тестах не выполняются.
